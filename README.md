# Security audit and fixes for inputs.py

Overview
========
This workspace contains a small Flask application `inputs.py` and an automated security audit. The original file has been backed up as `input_backup.py`. This repository contains patches, automated tests, and a report listing the vulnerabilities found and their fixes.

Files generated
===============
- `input_backup.py` - Backup of the original, vulnerable implementation.
- `inputs.py` - The patched, secure implementation.
- `report.json` - Structured JSON report of vulnerabilities and fixes.
- `tests/run_tests.py` - The test suite used to verify vulnerabilities in backup and confirm fixes in the patched file.
- `run_test.sh` - Shell script for running security tests on Unix-like systems.
- `run_test.bat` - Batch script for Windows to run tests.
- `auto_test.py` - Auto test runner that detects environment, executes tests, and logs to `logs/test_run.log`.
- `requirements.txt` - Python dependencies for tests and running the app.
- `Dockerfile` - Containerized environment for running the tests.
- `setup.sh` - Setup script for Linux/macOS.
- `logs/test_run.log` - Log file generated by running `auto_test.py` or test scripts.

Setup instructions
==================
1. Create a virtual environment (recommended):
   - On Linux/macOS: `python3 -m venv venv; source venv/bin/activate`
   - On Windows: `python -m venv venv; venv\Scripts\activate`
2. Install requirements:
   - `python -m pip install -r requirements.txt`
3. Set required environment variables (as needed):
   - `ADMIN_API_KEY` - API key for protected endpoints
   - `PAYMENT_TOKEN` - Payment token (simulated)
   - `INTERNAL_AUTH` - Auth secret for token generation
4. For testing, create the DB and test data by running `python tests/run_tests.py` which sets up a temporary DB in the tests folder.

How to run tests
================
- On Linux/macOS:
  1. Ensure `setup.sh` dependencies are installed.
  2. Run `./run_test.sh`.
- On Windows:
  1. Run `run_test.bat`.

How to use `auto_test.py`
=========================
`auto_test.py` detects your current environment and runs the appropriate test script (`run_test.sh` or `run_test.bat`). It writes detailed results to `logs/test_run.log`, including timestamps and final status lines.

To run:
```
python auto_test.py
```

Interpreting the logs
=====================
- Logs are stored at `logs/test_run.log`.
- Each run contains timestamps, STDOUT and STDERR of the test script, and the final status `TEST PASSED` or `TEST FAILED`.
- A JSON version of the test results is written to `tests_report.json`, showing per-module vulnerability checks.

Notes and Tips
==============
- The secure version of `inputs.py` reads sensitive values from environment variables rather than storing them in source code.
- The patched code fixes SQL injection, command injection, SSRF issues, and adds basic access control for sensitive endpoints.

If you need extra tests or to integrate these into CI, you can use the Dockerfile to create a repeatable environment.
